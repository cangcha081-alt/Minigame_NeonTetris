# NEON TETRIS · 技术风险与分阶段开发计划

版本0.3 · 2026-11-06。包含第六阶段后的方案A美术返工；本文件不授权越过用户要求的阶段暂停。旧工程结构属于规划历史，当前事实见PROJECT_CONTEXT。

## 一、技术方案与职责边界

用户已认可原生 HTML、CSS、JavaScript、Canvas 2D、Web Audio API 和 localStorage，通过本地 HTTP 服务运行。首版无需框架、打包器和第三方运行时库。可增加最小 package.json 统一 ESM 和开发/测试命令，但本阶段不创建。

| 模块 | 职责 | 边界 |
|---|---|---|
| core | 棋盘、方块、随机队列、碰撞、旋转、锁定、消行、计分 | 不访问 DOM、Canvas、音频或存储；允许注入时间和随机源 |
| input | 键位映射、输入边沿、长按节奏、焦点与默认行为 | 只提交动作，不修改棋盘数组 |
| game/session | 新局、暂停、继续、结束、重开及事件结算 | 统一管理规则时钟和生命周期 |
| render | 棋盘、方块、Ghost、预览与 DPR 适配 | 只读规则快照；不在绘制中计分或出块 |
| ui | DOM 面板、HUD、弹层、焦点、设置 | 管理界面状态；不会因打开设置自动继续 |
| audio | 原创乐谱、音乐调度、事件声音、音量和节点清理 | AudioContext 时钟独立于游戏循环 |
| effects | 旧行快照、局部动画、全局亮度限流 | 不写入规则数据；遵守减少/关闭模式 |
| storage | 版本化偏好、最高分读写与校验 | 异常降级到内存，不影响出块 |

采用单一帧调度入口驱动规则和绘制，规则用独立时间步进/事件时间推进；不以每帧走一格实现速度。音频单独维护可停止的短前瞻调度器。开始、暂停、结束与重开必须有完整清理路径。

后台 rAF 可能暂停，因此页面隐藏时进入暂停并清空输入，恢复时建立新的时间基准，不追赶几分钟的下落。依据 [MDN requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)。

## 二、技术风险分析

| 风险 | 概率/影响 | 规避方案 | 验证方法 |
|---|---|---|---|
| 旋转中心、墙踢坐标或 y 轴方向错误 | 中/高 | 先固化 SRS 90°数据与坐标转换，再写边界黄金样例；O 无位移旋转独立处理 | 七形状、两方向、四朝向、贴墙/地板/堆叠、失败不变 |
| 顶部出生、隐藏行与消行顺序歧义 | 中/高 | 使用规则文档的两行生成区及“消行后顶部判定”；不混用其他版本规则 | 生成碰撞、Hold 受阻、隐藏行残留与被消行救回 |
| 锁定刷新、软降计分和重复硬降漏洞 | 中/高 | 输入边沿和时间分离，单一垂直推进机制，每块刷新上限 | 499/500 ms 边界、15/16 次刷新、零距离硬降、持键换块 |
| 游戏状态与设置状态穿透 | 中/高 | 规则状态与弹层分开；明确返回目标；暂停按钮执行目标动作；Shift 独立释放才 Hold | P/Esc 长按、表单 Space、Tab/Shift+Tab、暂停按钮 focusout＋click、设置进出、重开取消 |
| 音频自动播放被拒 | 高/中 | 用户开始手势启用；失败捕获并允许无声游玩 | 新会话、静音、恢复失败与再次点击启用 |
| 音乐漂移、暂停后重复或重开叠音 | 中/高 | AudioContext 时间排程，保存乐曲位置，取消旧音符及增益自动化 | 两轮循环、10 次暂停/重开、结束淡出中重开 |
| 连续操作形成刺耳音效或输出削波 | 中/中 | 事件限频、声部上限、短包络、奖励仲裁、输出峰值检查 | 持续移动/软降＋四消升级组合听测 |
| 故障艺术降低识别或造成不适 | 中/高 | 低强度局部效果、全局限流、减少模式、静态风格成立 | 录屏、效果组合、系统偏好与无动画游玩 |
| Canvas 发光、像素处理导致卡顿 | 中/中 | CSS 静态纹理、缓存背景、限制粒子与 DPR，不做逐帧全屏通道读取 | 标准与关闭效果对比、帧耗时采样 |
| 存储被拒、损坏或来源变化 | 中/中 | 版本化校验、异常降级、固定 HTTP 来源；不依赖 file 协议 | 模拟抛错、非法 JSON、旧版、换端口说明 |
| 仅 Edge 可用导致跨浏览器验收不足 | 中/中 | 明确当前可用范围，后续检查 Chrome/Firefox 或记录实际未测项 | 浏览器版本与真实结果清单 |
| 中文路径、同步目录或受限环境影响工具 | 中/中 | 路径正确引用；按需核实端口和依赖下载；不把同步目录名当同步事实 | 后续实际启动命令和错误记录 |
| 项目文档在长对话后失真 | 中/高 | 阶段开始读四份记忆；事实/建议/通过结果分开；保留决策历史 | 交接审查、需求编号与验收追踪 |

localStorage 按来源保存，可能因浏览器策略无法访问；数据回退不应阻塞游戏，见 [MDN localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)。

## 三、验证策略

1. 规则单元测试：Node.js 内置 test/assert，固定随机源和虚拟时间，不引入为规则测试服务的 DOM 模拟库。对同一时间化输入以 60/144 Hz 绘制节奏驱动并比较结果；覆盖锁定到期与输入完全同刻的顺序。
2. 模块集成测试：输入到规则、事件到 HUD 数据、持久化失败、暂停/重开生命周期；使用可替换音频/存储边界验证业务，不用假声音证明真实听感。
3. 浏览器验证：先在本机 Edge 验证，再核实 Chrome/Firefox 条件。若引入 Playwright 等开发工具有明确收益，再说明安装与维护成本；本阶段不安装、不承诺其已经可用。
4. 人工体验：按键手感、音乐循环接缝、四消成就感、字体层级、Ghost 可读性和减少效果。主观观察应附场景与结论，不能用单元测试代替。
5. 性能记录：浏览器/硬件/视口/DPR/刷新率/效果模式、采样时长、帧工作量 P95 与长帧；先建立基线再决定优化。
6. 设计阶段只进行文档一致性、相对链接、需求编号和曲线/色彩数值检查；功能验收全部保持“未执行”。

## 四、分阶段开发计划

每个阶段先检查状态、读取项目记忆，结束后更新文档、列出八项汇报并暂停。详尽任务与并行条件见 TASK_PLAN.md。

| 阶段 | 范围 | 退出条件 |
|---|---|---|
| 一：环境探索（已完成） | 只读环境调查 | 已汇报，技术栈获认可 |
| 二：产品需求（已确认） | PRD、规则、视听与验收 | 用户确认 PRD，实际表现待实测 |
| 三：软件架构（已完成） | 模块接口、算法、事件与资源、任务和验证方案 | 审查、文档验证完成 |
| 四：最小工程（已完成） | T01及本轮要求的基础界面/模块接口 | HTTP/ESM真实可用，12项测试通过，浏览器基础布局已验证 |
| 五：核心规则（已完成） | T02～T06 | 新增54项核心/时间/审查测试通过；整套66项通过，UI接线尚未完成 |
| 六：美术界面及返工（本轮完成） | 原视觉被用户否定后，返工A诊断、用户确认A布局、返工B实现NIGHT SHIFT ARCADE | 78项测试通过；新机身/七色/状态/设置/事件与适配实查；未接完整输入/循环，审美仍待用户最终确认 |
| 七：运行整合与事件视觉（建议） | T07～T11剩余接线 | 完整基础游玩、状态/焦点/持久化及消行/硬降等视觉反馈通过 |
| 八：原创音乐与音效 | T12 | 实际浏览器与听测通过，无旧局资源残留 |
| 九：综合验收 | T13 | 全量AC与使用/课程记录，未测范围明确 |

T12 在接口冻结后可与界面链并行，不能借并行越过用户阶段暂停。完整软件交付不自动包含发布或推送。

第六阶段顺序按用户明确指令调整，旧的“先运行后美术”是建议历史，未被当作阻止美术的限制。当前完成后暂停；后续具体阶段范围以新指令为准。

方案A返工补充：数字/消行/硬降/结束的有限反馈已实现，T11剩余为真实高频游戏事件/闪光/性能与完整模式验证。音乐仍待音频阶段实际创作与听测；不可将设置面板或合成事件样张当作完整游戏交付。
