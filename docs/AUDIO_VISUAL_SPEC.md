# NEON TETRIS · 音乐、音效与动态视觉需求

版本0.3 · 2026-11-06。音频目标继续保留，编曲与实际输出未实现/试听；视觉返工已实现有限事件反馈，第六节覆盖旧V06/V07的表现方式。七类最终反馈和真实整局验收仍不能全部标完成。

## 一、原创音乐方案

1. 使用 Web Audio API 合成原创 16 小节循环曲，4/4 拍、112 BPM、A 小调方向，约 34.286 秒一轮。融合 Chiptune 的清晰脉冲旋律、Synthwave 的柔和铺底和低音节奏。
2. 编制建议：柔化方波/脉冲主旋律、三角波低音、低音量和声、短噪声军鼓/踩镲；频段留出空间给操作音效。前 8 小节建立主题，后 8 小节变奏回收，末小节自然回到首小节。
3. 本阶段只定义风格、结构与验收，不声称已经创作或试听过乐曲。后续必须写出原创音符与节奏数据，不复用商业旋律、现成游戏主题或无来源采样。
4. 音乐不随每次消行突然变速，不增加分等级曲库；首版一首完整循环曲即可。四消音效在同调性下形成短奖励动机。
5. 音乐、音效分总线控制，各自开关和音量。建议默认音乐开、35%；音效开、55%。开关关闭不把保存的音量改成 0。
6. 结束前的释放尾音应跨循环边界自然衔接，不在小节边界硬切增益；耳听至少连续两轮检验接缝、爆音和重复疲劳。

## 二、音频生命周期与容错

| 状态/操作 | 音乐行为 | 音效与资源行为 |
|---|---|---|
| 初始标题 | 静音，不预先播放 | 可延迟创建 AudioContext |
| 用户点击开始 | 在该手势中创建/恢复上下文，约 300 ms 淡入 | 播放开始提示；音频失败不阻塞出块 |
| 手动暂停 | 约 80 ms 降为静音并保存乐曲位置，取消已预排的新音符 | 暂停音效可独立播放；不能先挂起整个上下文导致提示音消失 |
| 打开设置 | 保持暂停，不自动恢复音乐 | 仅用户主动调整时做短预听；不触发游戏动作 |
| 继续 | 从保存的音乐位置重新调度，约 120 ms 淡入 | 播放继续音，避免重复启动调度器 |
| 切后台/失焦 | 停止调度并静音，回前台仍保持暂停 | 不播放突兀暂停音；清理尾音及旧任务 |
| 游戏结束 | 600 ms 淡出，随后停止音乐调度 | 游戏结束音独立播放；界面立即可操作 |
| 结束淡出中重开 | 取消旧淡出与全部旧局任务，音乐从开头重新建立 | 旧游戏结束音快速释放，不压住新开始提示 |
| 关闭音乐 | 约 50 ms 平滑静音并停止排程，保留当前位置 | 不影响音效；重新开启只在 RUNNING 时续播 |
| 关闭音效 | 约 20 ms 释放全部事件音 | 不影响音乐；不播放“关闭音效”提示音 |

调度建议：使用 AudioContext 时间，以约 25 ms 的调度检查提前安排约 100 ms 音符，避免把音符起点绑定到游戏帧。该数值是实现建议，需在浏览器验证；后台场景依靠暂停规则处理。

增益变化使用短包络避免爆音。声音节点结束后断开，重复重开不累积振荡器、定时器或总线。任何恢复 Promise 失败均捕获：显示非模态“声音未启用，可点击启用声音”，继续提供无声游戏，不循环弹窗。

依据：浏览器通常要求用户手势来创建或恢复可播放的音频上下文，见 [MDN Web Audio 最佳实践](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices)。

## 三、游戏音效需求表

表中时长和响度是设计目标，响度为相对音效总线的包络峰值，不是声压或实测音量。建议最多同时 8 个事件声部，限制重复事件，保证输出不发生数字削波；最终需听测和峰值检查。

| 编号 | 事件 | 声音设计 | 时长 | 相对峰值 | 触发/限频 |
|---|---|---|---|---|---|
| S01 | 游戏开始 | 三音上行启动动机 | 240 ms | 0.30 | 每局一次 |
| S02 | 方块移动 | 短促、轻量方波点击 | 25 ms | 0.10 | 仅成功移动，每 70 ms 最多一次 |
| S03 | 方块旋转 | 轻微上/下行双音；Q/E 方向可区分 | 55 ms | 0.16 | 仅有效变化，每 60 ms 最多一次 |
| S04 | 软降落 | 低音量数字脉冲 | 20 ms | 0.07 | 成功推进，每 100 ms 最多一次，不逐格强响 |
| S05 | 硬降落 | 短低频冲击＋细噪声尾部 | 120 ms | 0.32 | 每次硬降一次，零距离也有轻版本 |
| S06 | 方块固定 | 干净低中频落点音 | 55 ms | 0.18 | 自然锁定一次；硬降已反馈时省略独立固定音 |
| S07 | 消除一行 | 两音确认音 | 150 ms | 0.24 | 每次结算一次 |
| S08 | 消除两行 | 更宽的三音上行 | 210 ms | 0.28 | 每次结算一次 |
| S09 | 消除三行 | 明亮上行与短和声 | 280 ms | 0.32 | 每次结算一次 |
| S10 | 消除四行 | 独立奖励动机、和声展开、低频收束 | 480 ms | 0.40 | 四消专属，不能用单行音加大音量代替 |
| S11 | 等级提升 | 高音区三音上行标记 | 260 ms | 0.28 | 每次跨等级结算一次，四消同时发生时延后约 120 ms |
| S12 | 暂停 | 短下行双音 | 100 ms | 0.16 | 手动暂停一次，自动失焦暂停不播放 |
| S13 | 继续 | 短上行双音 | 100 ms | 0.16 | 主动继续一次 |
| S14 | 游戏结束 | 下行电子收束，保留柔和尾音 | 700 ms | 0.32 | 每局一次，重开可中止 |
| S15 | Hold（补充建议） | 克制的交换双音 | 70 ms | 0.14 | 仅有效暂存一次 |

音效反馈基于规则事件结果，不能在 keydown 时预先播放成功音。被拒绝的旋转、移动、重复 Hold 无成功音。O 旋转不改变占格，不播放旋转成功音。

同次结算优先级：游戏结束 > 四消 > 其他消行 > 升级 > 硬降 > 固定 > 普通操作。处理方式为选择或错峰，不把所有高优先级事件无限叠加：

- 有消行时省略独立固定音；硬降冲击可保留为短起音，消行奖励略后进入。
- 四消与升级同时发生时，四消完整表达，升级标记延后约 120 ms 且适当降低；必要时音乐短暂降低约 3 dB 后平滑恢复。
- 顶部失败同次结算若含消行，保留数值奖励与文字，声音以结束收束为主，省略长消行和升级音。
- 音效关闭优先于所有奖励；连续播放的声音总量要经过总输出峰值检查，不能只靠表内峰值之和推测不削波。

|---|---|---|---|---|---|
| V01 | 消行闪光 | 对应行一次低强度青色亮起并消退 | 120 ms；仅旧行位置；叠层 alpha ≤0.18 | 无亮闪，80 ms 低对比渐变或即时文字 | 即时棋盘结果与分数 |

| V06 | 游戏结束 | 棋盘降低亮度，结果层渐入 | 450 ms；保留最终棋盘；不延迟按钮可用 | 100 ms 渐变 | 立即显示结果 |
| V07 | 菜单切换 | 标题/面板 1～2 个切片与短 RGB 偏移 | 160 ms；最多 ±3 px；不扭曲进行中的棋盘 | 100 ms 淡入，无位移/色差动画 | 立即切换 |

### 4.1 统一约束

1. 整局无高强度全屏闪烁、无交替饱和红色闪屏。亮起采用单峰，不做明暗明暗往复。
2. 事件合并后，全局任意滚动 1 秒内最多允许两次明显亮度峰值；额外奖励用稳定文字或轮廓替代。该限流由统一效果层执行，不让多个事件各自计数。
3. 四消已覆盖多行光效，不再同时运行 V01、V02；升级仅在侧栏出现；游戏结束可中止其他装饰反馈。
4. 粒子是可选表现，不是额外必须功能；如采用，上限 32 个、寿命 ≤250 ms，减少/关闭模式完全停用。
5. 特效不占用游戏锁定时间，不改变碰撞数据，不阻塞新块控制；旧行叠层在活动块下方或只画细轮廓。
6. 暂停停止进行中的装饰反馈；继续时清理残余短特效，不补播。设置为减少或关闭应立即取消不符合要求的活动效果。
7. 静态扫描线、像素网格和低对比纹理属于主题；可保留，但须满足可读性。它们不通过快速移动模拟 CRT。

参考 [W3C 闪光阈值说明](https://www.w3.org/WAI/WCAG22/Understanding/three-flashes-or-below-threshold.html)：闪光风险涉及频率、亮度和面积，不能仅凭时长或单个效果宣称符合标准。本项目选择更保守的局部单峰与总量限制，最终仍需录屏检查，不声称已完成无障碍认证。

## 五、六项设置与优先级

| 设置字段 | 建议默认值 | 范围/语义 |
|---|---|---|
| musicEnabled | true | 游戏开始后才播放，不自动播放标题音乐 |
| musicVolume | 0.35 | 0～1，界面显示 0～100%；音量为 0 视为听感静音但不更改开关 |
| sfxEnabled | true | 控制全部事件音及音效预听，不控制音乐预听 |
| sfxVolume | 0.55 | 0～1，界面显示 0～100% |
| effectsEnabled | true | 总开关，只控制装饰动画，不停用基础方块移动 |
| reduceMotion | null | null 表示未显式选择，采用系统偏好；boolean 表示用户显式覆盖 |

有效模式：effectsEnabled=false → 关闭；否则用户显式 reduceMotion 优先，其次读取系统 `prefers-reduced-motion`，为 true 则减少，否则标准。

- UI 只有用户要求的六项设置，不额外增加必须操作的模式菜单。减少动态复选框显示当前有效偏好；用户主动修改后保存显式布尔值。仅调整音量不得把未选择的 null 自动改成 false。
- 系统偏好变化时，仅在 reduceMotion=null 的情况下跟随；总开关关闭时减少选项禁用但保留原值。
- 关闭动态效果后，音乐与音效不变；关闭音乐或音效不改变画面。减少动态效果不降低游戏重力、软降或锁定速度。
- 音量设置和存储失败的行为见 GAME_RULES §八。保存应节制：滑块拖动即时试听，保存可短暂合并，结束拖动立即尝试最终保存。
- 音乐开关在 PAUSED/设置层开启时只改变偏好，不恢复整曲；可主动点击滑块调节时做 ≤500 ms 的短音色预听，结束后保持暂停。音量为 0 或开关关闭时不预听。

系统偏好来源见 [MDN prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)。

## 六、NIGHT SHIFT ARCADE返工覆盖

用户确认工业街机方向，要求区别机械、数字与信号反馈。普通菜单不再采用旧V07通用RGB/位移Glitch，改为140ms局部裁切显现；印刷标题不动画。V06结束为一次420ms局部±1px/低强度色差，约65%进程后保持稳定，减少模式100ms透明度、关闭立即显示。不能让结果按钮等待动画。

V01/V02/V05当前用真实消除行的透明旧格残影横向收束，单/多行150ms、四消200ms，alpha峰值.14/.18；新消行替换旧残影不叠亮。没有全屏闪光、随机噪点或粒子。四消有黄绿文字标记；V03硬降80ms机柜1px以内、与消行同批时省略冲击，零距离不冲击。V04独立数值确认与400ms文字。数值本身立即更新，不滚动或缓动计分。

声音尚未实现。本轮音乐设计约束：延续原创112BPM/A小调，偏干燥脉冲、三角低音与克制打击，避免用巨大混响替代氛围；不改变16小节/独立总线/手势启动等已确认接口。后续须实际听测与循环资源验收，不能因音量设置可操作便声称有电子音乐。

V01/V02/V05：旧行先低强度高亮再单向扫描，普通140ms、四消180ms，alpha峰值.16/.20，替代第六节150/200ms与.14/.18参数。滚动一秒最多2次行亮度反馈，超出仅省略行动画，数值与文本不丢失；限制保留跨局的一秒窗口，避免通过重开绕过。最多4行，新动画替换旧行，完成/取消释放节点。减少与关闭模式均不生成行扫描。V03/V04/V06仍按第六节；暂停遮罩增加140ms局部显现，仅状态改变时执行，不随重复render触发。没有新增音频功能。

## 八、第七阶段实际音画整合（2026-11-07，当前覆盖）

旧“声音未实现”属于前阶段历史。现已写出原创NIGHT SHIFT的16小节MIDI音符/节奏数据，112BPM约34.286秒；方波主线、三角低音/和声、正弦电子鼓与轻方波节拍，15事件音用独立短包络合成，无外部音频。声音音质/两轮接缝/真实峰值尚未试听或测量，不能据此承诺无削波。

单AudioContext与双总线；用户手势创建/resume，失败返回状态、无声继续并允许设置重试。音乐25ms检查100ms前瞻，不绑定rAF；暂停80ms释放并存位置，继续120ms淡入，开始300ms淡入，结束600ms停止节点，重开复用Context且清旧自动化/声音。音效使用音频时钟错峰，无额外延迟JS timer；最多8源、MOVE/ROTATE/SOFT分别70/60/100ms限频。同批消行选对应CLEAR_1～4，省略硬降/固定独立音；四消升级延120ms。自动失焦/隐藏/设置暂停不发手动PAUSE提示。

短预听约300ms，独立资源、不推进暂停音乐；对应开关/音量归零取消，无关总线不干扰。App等待手势解锁后验证请求版本和设置仍打开，防止迟到预听。关闭面板/失焦/换局/dispose停止预听。Context.close拒绝被捕获。

V01/V02/V05参数再次细化为1/2/3/4行alpha .14/.16/.18/.20及140/150/160/180ms；四消交替青/黄绿局部彩带，不新增第二峰值。保持1秒最多2次反馈、最多4行及16动画资源。V04显示LEVEL UP，消行/升级同时发生时后者占最终文字槽。V06遮罩opacity .1→.75→.9→1单调加深，420ms短色差、65%后归稳；减少模式100ms透明度，无扫描/冲击/Glitch，关闭不创建装饰动画。规则不等待光效，声音和动画关闭均不改变计分/速度。

真实Engine到音画链路及资源自动化通过，浏览器Context running和暂停调度0部分实查；普通浏览器持续游玩、实际听音/峰值仍未完成。证据与12项状态见STAGE_07_REPORT。
